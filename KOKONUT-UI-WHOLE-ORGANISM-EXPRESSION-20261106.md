## Eight-lens binding — why a component belongs

For each candidate component, create an explicit CCK/actor profile with:

1. **Identity & purpose:** application, cassette, element ID, original founder request, audience, decision owner, source/licence pin.
2. **Reaction:** pointer, touch, hover and keyboard trigger; accessible alternate action.
3. **State:** initial, pending, accepted, refused, failed, disabled, cancelled, rollback/undo, and reconnect.
4. **Transformation:** visual change; Chromatophore appearance/structure/payload and Morph Law rebind plan without changing original identity, work or saved draft.
5. **Navigation:** focus and route after activation, return to original control and selected work ID.
6. **Calculation:** input, limits, rounding, source, latency and whether the number is only a visual demonstration.
7. **Communication:** explicit event payload, target owner, permission check and actual response/receipt, never a simulated request promoted to reality.
8. **Adaptation and persistence:** light/dark, motion preference, contrast, small-screen/voice, offline/restart and owner readback; continuous state and source revision.

These are facets of one behavior, not eight separate engines or a new permissions system. A typical record follows: **intent → current state → physical metaphor → allowed user event → approval/owner action → real result → recovery → independent receipt**.

## Native-first, no secret permissions

For ACT/Automata, preserve the existing rail slot geometry, cassette and host controls. React components must go into an **authorized React/Next projection** of an actual owner app. SwiftUI/Apple HIG remains the native Apple chair; a React component cannot be “installed” into SwiftUI without a genuine, separately built native equivalent. WordPress/Briefcase persists authorized content; protected commands go through the existing Approval Engine; the UI reflects only actual owner readbacks. On a private local Studio, upstream source download or any network registry install requires explicit scope and source/licence review, with no personal data sent to public services.

**Human acceptance:** on the real target, demonstrate pointer, touch and keyboard, reduced motion, screen reader name, visible focus, real success/refusal, reload/return and accessibility contrast; record source revision, installed route, test time, owner and replayable independent evidence. If only a static specimen or local prototype exists, say **source specimen** and mark runtime **HOLD**.
