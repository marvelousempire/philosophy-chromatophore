# Behavior as a first-class Chromatophore node

**Founder instruction, November 5, 2026:** Define behavior as what an interface or software organism does in response to an occurrence, not merely its animation. Treat it as first-class alongside form while preserving the complete Chromatophore philosophy.

## Scope reminder

Chromatophore is the **whole coherent adaptive organism**, including node birth/identity, meaning, form, behavior, function, computation, authorization, operation, evidence and continuity. It is **not** a GUI skin, a rendering engine, frontend/backend wiring, or a synonym for Morph Law. The existing octopus, nonagon, brain precedent, Morph Law, Optimus Instant, actor and Semantic Node doctrines are retained. This file is a concrete *behavior* expression of the whole; it does not replace those doctrines.

## The eight orthogonal behavior lenses

| Type | Core question | Example |
| --- | --- | --- |
| Reaction | What event is sensed? | Hover, focus, click, native form submission |
| State | Which condition changes? | Selected, open, pending, denied |
| Transformation | How is form or arrangement rebound? | Card expands, tile morphs |
| Navigation | What surface, focus or route is entered? | Avatar opens approved member profile |
| Calculation | What information is derived? | Dimensions, totals, contextual rankings |
| Communication | What data moves and between whom? | Fetch/AJAX request, source-bound receipt |
| Adaptation | How does behavior respond to conditions? | Viewport, reduced motion, user preferences |
| Persistence | What survives change, refresh or return? | Saved profile, retained draft, owner readback |

These are classification facets, not eight mandatory engines or a claim that every action must instantiate all eight. Behavior may involve several categories. Source classification does not equate to runtime proof. Word grammar classification belongs to classifyTHAT; UI role inventory belongs to roleCallTHAT.

## Canonical contract anatomy

Every specified behavior requiring traceability has a **source-linked** stable identity and the following slots:

1. **Trigger:** the initiating occurrence and element.
2. **Condition:** the exact prerequisite and evaluation owner.
3. **Action:** the requested native behavior, scripted operation or owner effect.
4. **State change:** before/after, with presentation/client/owner scope clearly distinguished.
5. **Feedback:** what the person observes, explicitly separated from actual success.
6. **Owner:** which real actor/product grants permission and controls effects.
7. **Evidence:** source/revision and actual level of proof; no fabricated commissioning.
8. **Continuity:** stable work ID, source, draft, focus and other retained state.

Form describes what appears. Behavior describes the transition or response. Function describes what the system is authorized and actually able to accomplish. These distinctions may coexist in a single node, and changing form must not secretly change function or authority.

## Tier expression, not three competing Chromatophores

**Super Fast Look:** native HTML/CSS states, links, forms, disclosure, responsive behavior, transitions and motion. No client-side JavaScript. A native HTML form can ask a server to do work but doesn't prove the server accepted anything.

**Very Fast Look:** inherits native HTML/CSS, adds plain JavaScript for programmable conditions, calculations, client state, Fetch/AJAX, conditional navigation and in-browser review/return. jQuery can be used for legacy compatibility but is not required for AJAX. A Fetch response is not automatically proof of owner-authorized persistence.

**Fast Look:** qualified FlowTHAT/ACT review/player and actual authorized product owner, permission checks, service effects, save/readback and independent receipts. This extends, not replaces, the first two appearance and behavior vocabularies.

**Executable candidate:** [Morph Law PR #3](https://github.com/marvelousempire/morph-law/pull/3) adds `chromatophore.behavior/v1` pure contract/audit/proposal helpers. Those helpers cannot perform operations or certify that a submitted receipt is real. Canonical Gitea owner admission and real consumer tests remain separate.
